# City Universe — 极端天气 × 城市物流仿真

> **LLM 生成 agent「灵魂」 × 规则引擎城市仿真**：让 AI 一次性塑造 5 位外卖骑手的身份、
> 性格与动机，再把他们扔进一座即将被暴雨吞没的城市，看每一笔订单如何在极端天气里
> 减速、绕行、延误，甚至被取消。

这是一个**纯静态、零依赖、零 API Key** 的可交互演示（demo）。双击 `index.html` 即可
从头点完一遍完整流程，无需安装任何环境、无需配置后端。

---

## 一句话原理

1. **LLM 生成骑手「灵魂」**：为每位骑手生成身份、年龄、性格、动机与座右铭，并蒸馏成
   `风险耐受 / 速度 / 收入敏感` 三个行为参数。
2. **规则引擎推进时间**：在城市网格里逐 tick 模拟下单 → 派单 → 取餐 → 配送 → 送达 / 取消。
3. **极端天气冲击一切**：暴雨/暴雪降低配送速度、封路积水迫使绕行、等待过久触发顾客取消。
4. **LLM 复盘**：最后生成《城市日报》与每位骑手的第一人称复盘。

## Demo 怎么玩（5 步交互）

页面顶部有进度条，可从头点到底，也可回看已完成的步骤：

| 步骤 | 内容 |
|---|---|
| ① 开始 | 选一个天气剧本 |
| ② 生成宇宙 | 点「▶ 开始生成」→ 展示城市设定 + 5 位骑手的「灵魂」（身份 / 性格 / 动机 / 座右铭 + 三个行为参数） |
| ③ 运行模拟 | 点 ▶ 逐 tick 播放城市网格动画（骑手移动 / 天气变化 / 积水封路）、配送效率曲线、宇宙直播流 |
| ④ 结果洞察 | 晴雨分段指标、骑手绩效对比、订单明细（可点击表头排序） |
| ⑤ 城市日报 | LLM 撰写的《城市日报》与每位骑手的第一人称复盘 |

### 四个天气剧本

同一座城市、同一批骑手，只改变天气，便于对比：

| 剧本 | 订单数 | 取消率 |
|---|---|---|
| 全天晴朗 | 24 | 0% |
| 晴 → 暴雨 → 晴 | 21 | 33% |
| 暴雪 | 22 | 27% |
| 极端暴雨 | 28 | 61% |

**方式一：双击打开**（最快）

直接双击 `index.html`，用浏览器打开即可。

**方式二：在线访问**（本仓库已开启 GitHub Pages）

访问 <https://ziyiblazer.github.io/city-universe-demo/> 即可直接体验。
打开后按页面上的「怎么玩」提示操作即可：**选天气 → 点「▶ 开始生成」→ 点「进入模拟」

## 数据从哪来

`data.js` 里的所有数据都是**预先跑好、固化下来的**，因此 demo 端不需要后端和 API Key。
数据由完整版系统的本地后端生成（LLM 生成骑手灵魂与日报，规则引擎跑完整仿真），
再固化成一个 JS 文件。

如需重新生成数据（需本地后端在 `127.0.0.1:5001` 运行）：

```bash
python generate_data.py
```

## 项目完整版预想（Roadmap）

当前这个 demo 是完整版系统的一个**可离线分发的「切片」**——它展示了核心体验，
但把「生成」与「仿真」的过程预先固化成了静态数据。完整版的目标是把它变成一个
**可交互、可实验、可研究的城市物流多 agent 仿真平台**：

### 第一阶段 · 可交互实验平台（进行中）
- 用户实时调参：城市规模、骑手数量、订单率、天气强度、雨天补贴策略等；
- 一键跑仿真、保存运行记录、横向对比不同参数/天气下的结果；
- 前后端分离（Flask + Vue），LLM 通过 API 接入（无 Key 时自动回退到确定性模板）。

### 第二阶段 · 真正的多 agent 智能
- 骑手从「固定行为参数」升级为 **LLM 实时决策**：每一 tick 自主判断接单 / 拒单 /
  绕行 / 收工；
- 多个 agent 之间、agent 与环境（天气、封路、订单池）实时交互；
- 观察涌现行为：抢单、内卷、互助、风险偏好如何影响个体收入与整体效率。

### 第三阶段 · 更真实的城市与经济
- 真实路网与交通拥堵，替代抽象网格；
- 多业态扩展：外卖 / 生鲜 / 快递 / 网约车；
- 供需匹配算法与平台补贴的经济学实验：骑手留存、收入公平、系统韧性。

### 长期 · 从「演示」到「研究 / 教学」
- 作为 **Agent-Based Modeling（ABM）** 的教学工具；
- 作为研究「极端天气下城市配送韧性」「平台劳动与算法治理」的实验沙盒；
- 支持策略干预的因果对比（例如：暴雨补贴到底能不能留住骑手、降低取消率）。
